# 처음 오셨다면

이 문서만 따라 하면 첫 이슈를 시작해서 PR까지 올릴 수 있어요. 막히면 **막힌 화면 캡처 + 터미널 메시지**를 디스코드에 올려 주세요.

## 0. 먼저 알아 둘 말

| 말 | 뜻 |
|---|---|
| 와이어프레임 | 화면 설계도. `docs/wireframe.html`을 브라우저로 열면 볼 수 있어요. 우리는 이걸 **그대로** 옮겨요 |
| 보드 | 와이어프레임의 그림 한 장. 같은 화면이라도 상태마다 따로 있어요. 예: `S15_내계약서_목록`, `S15_내계약서_빈상태` |
| 이슈 | 할 일 한 묶음. 보통 화면 하나 = 이슈 하나이고, 그 안에 보드 체크리스트가 있어요 |
| 브랜치 | 내 작업 공간. 이슈마다 하나씩 만들어요. 예: `feat/ELICE-15-my-contracts` |
| PR | "내 작업을 `dev`에 합쳐 주세요"라는 요청. 팀원 1명이 승인하면 합칠 수 있어요 |
| `dev` | 팀이 함께 쓰는 기준 코드. **여기에 합쳐져야(머지) 이슈가 완료**예요 |
| 환경 설정 (`.env.local`) | 내 PC에서만 쓰는 설정 파일. GitHub에 올라가지 않아요. `.env.example`을 복사해서 만들어요 |
| `VITE_API_MODE` | 환경 설정 값 중 하나. API를 진짜로 부를지 정해요. **`real`**(로컬 기본): 백엔드에 만들어진 API는 진짜로 부르고 나머지는 자동으로 mock · **`mock`**: 전부 mock (배포 주소가 이거예요) |
| mock | 가짜 응답. 백엔드에 아직 없는 API는 프론트에 적어 둔 예시 데이터(`src/api/mocks/`)로 답해요 |

## 1. 설치 (처음 한 번)

1. **Node.js** LTS: https://nodejs.org → 설치 후 터미널에서 `node -v`가 나오면 성공
2. **Git**: https://git-scm.com/downloads
3. **Docker Desktop**: https://www.docker.com/products/docker-desktop → 설치 후 **실행해 두기**(백엔드를 띄울 때 써요. Java·DB는 설치하지 않아도 돼요)
4. **GitHub CLI**: https://cli.github.com → 설치 후 터미널에서 `gh auth login` (Claude가 이슈·PR을 다룰 때 써요)
5. **Claude Code**: 설치하고 로그인
6. **GitHub**: 메일로 온 EliceAi 조직 초대를 수락 (7일 지나면 만료돼요)

## 2. 첫 실행

프론트와 백엔드를 **같은 폴더 안에 나란히** 받아요. 백엔드를 띄울 때 옆 폴더(`../docAi-be`)를 찾아요.

```bash
mkdir elice-ai
cd elice-ai
git clone https://github.com/EliceAi/docAi-be.git
git clone https://github.com/EliceAi/docAi-fe.git
cd docAi-fe
npm install
```

`.env.example` 파일을 복사해서 이름을 `.env.local`로 바꿔요. 내용은 그대로 둬요.

```bash
npm run backend
npm run dev
```

- `npm run backend`: 백엔드와 DB를 Docker로 띄워요. **처음 한 번은 3~5분** 걸려요(이미지·라이브러리를 받아요). `npm run backend:logs`에서 `Started DocaiApplication`이 보이면 다 켜진 거예요(Ctrl+C로 로그 보기만 끝내요). 다음부터는 몇 초면 켜져요.
- `npm run dev`: 프론트 서버. 터미널에 아래 주소가 나와요. **작업하는 동안 이 터미널은 켜 두세요**(닫으면 꺼져요).

## 3. 화면 확인하는 곳 두 군데

| 주소 | 무엇을 보나 |
|---|---|
| http://localhost:5173 | **실제 앱.** 사용자처럼 처음부터 눌러 보며 동작 확인 |
| http://localhost:5173/dev/boards | **보드 모아 보기.** 와이어프레임 보드 전체가 흐름 순서대로 칸으로 나와요 |

**보드 모아 보기(`/dev/boards`) 쓰는 법**
- 맨 위 카드: 전체·김지희·구자건 진행률. 담당자 카드를 누르면 그 사람 보드만 진하게 보여요
- 칸 색: **파랑 = 김지희, 초록 = 구자건.** 색이 꽉 찬 칸은 완료, 점선 칸은 아직
- 칸을 누르면 오른쪽에 그 보드 상태가 휴대폰 크기로 크게 나와요
  - **앱에서 열기**: 실제 앱의 그 화면으로 이동
  - **와이어프레임 원본**: 같은 보드의 설계도를 새 탭으로 열어 나란히 비교
- 주소 뒤에 보드 이름을 붙이면 바로 그 보드가 열려요: `/dev/boards#S15_내계약서_목록` (Claude도 이 주소로 알려 줘요)
- 내 PR이 머지되면, `dev`를 받은 모든 사람의 화면에서 그 칸이 완료로 바뀌어요

**휴대폰 크기로 보기 (PC에서)**: 크롬에서 **F12 → Ctrl+Shift+M**(기기 모드) → 위쪽에서 `iPhone 12 Pro` 같은 기기를 고르면 390px 휴대폰 화면이 돼요. PC 너비에서는 가운데 휴대폰 틀 + 옆 소개가 보이는 게 정상이에요.

## 4. 일하는 방법: 말 세 마디

**할 일(이슈)은 이미 만들어져 있어요.** 이슈를 새로 만들 필요 없이, 내 이름이 담당자로 지정된 이슈를 **번호가 작은 것부터 순서대로** 하면 돼요.
- 내 이슈 보기: https://github.com/EliceAi/docAi-fe/issues/assigned/@me 또는 Claude에게 "내 이슈 보여줘"
- 이슈 하나 = 화면 하나. 이슈 안의 체크리스트가 만들 보드 목록이에요.
- 한 이슈를 PR까지 올리고 나면 다음 이슈로 넘어가요. 승인을 기다리는 동안 다음 이슈를 시작해도 돼요.

`docAi-fe` 폴더에서 Claude Code를 켜고 이렇게 말하면 돼요. Claude가 매번 마지막 줄에 다음에 할 말을 알려 줘요.

| 이렇게 말하면 | Claude가 하는 일 |
|---|---|
| **"15번 이슈 할게요"** | 이슈 읽기 → 브랜치 만들기 → **계획 보여 주기(승인하면 시작)** → 보드를 하나씩 옮기고 이슈 체크 → 보드마다 확인 주소 안내 |
| **"확인해줘"** | 빌드, 와이어프레임과 비교, 규칙·수정 범위 검사 → 빠진 것 알려 주기 |
| **"PR 올려줘"** | 커밋 → push → PR 작성 → 주소 알려 주기 |

그 밖에 쓸 수 있는 말:
- "다음 이슈 할게요": 내 담당 이슈 중 아직 열려 있는 가장 작은 번호를 골라 시작해요
- "내 이슈 보여줘": 내 담당 이슈 목록과 진행 상태를 보여 줘요
- "커밋해줘": 중간에 저장하고 싶을 때
- "PR 의견 반영해줘": 팀원이 PR에 의견을 남겼을 때
- "N번 PR 봐줘": 팀원 PR을 확인할 때 (승인 버튼은 직접 눌러요)
- "○○ API 연결 확인해줘": 백엔드에 API가 새로 머지됐을 때 실제 연결을 확인하고 켜요

**Claude가 계획을 보여 주면** 보드 순서·만들 파일·쓸 부품을 훑어보고 괜찮으면 "응"이라고 하면 돼요. 이상하면 그냥 말로 고쳐 달라고 하세요.

## 5. 저장소에서 저절로 일어나는 일

| 언제 | 무슨 일 | 나는 뭘 하면 되나 |
|---|---|---|
| `dev`·`main`에 직접 올리려 하면 | 막혀요 | 항상 작업 브랜치 → PR (Claude가 알아서 해요) |
| PR을 올리면 | 빌드 검사가 자동으로 돌고, 디스코드에 "리뷰 요청" 알림 | 빌드가 빨간불이면 "빌드 실패 고쳐줘" |
| 팀원 1명이 승인하면 | 디스코드에 "머지 가능" 알림 | PR 화면에서 **Merge pull request** |
| 머지되면 | `Closes #N` 이슈가 자동으로 닫히고, GitHub의 작업 브랜치가 자동으로 지워지고, 디스코드 "머지" 알림 | "다음 이슈 할게요" (dev 받기·로컬 브랜치 정리는 Claude가 해요) |

## 6. 환경 설정: mock과 real

- `.env.local`(환경 설정 파일)의 `VITE_API_MODE` 값으로 정해요. 로컬은 `real`이 기본이에요. 백엔드에 만들어지고 확인된 API(`src/api/mock-mode.ts`의 `READY_APIS`)만 진짜로 부르고, 나머지는 자동으로 mock으로 답해요. 그래서 **백엔드 API가 없어도 화면 작업은 막히지 않아요.**
- 배포 주소(Vercel)는 백엔드가 없어서 전부 mock이에요. PC 화면 아래 "시연 모드" 문구가 그 표시예요.
- 화면 코드는 mock인지 real인지 몰라요. 항상 `src/api/` 함수만 부르면 돼요.

**API가 진짜로 불리는지 직접 보고 싶을 때**: 크롬 F12 → **Network** 탭 → 필터에 `api` 입력 → 화면을 눌러 보면 `/api/...` 요청과 응답이 줄로 보여요. 줄을 누르면 보낸 내용(Payload)과 받은 내용(Response)을 볼 수 있어요.

## 7. 휴대폰으로 보기 (카메라·촬영 화면을 볼 때만)

평소에는 PC 브라우저로 충분해요.

1. PC와 휴대폰을 **같은 와이파이**에 연결해요.
2. 터미널에서 `npm run dev:phone`을 실행하고 켜 둬요(`npm run dev`가 켜져 있으면 Ctrl+C로 먼저 꺼요).
3. 터미널에 나온 `Network:` 주소를 휴대폰 브라우저에 입력해요. 예: `https://192.168.45.29:5173` (숫자는 PC마다 달라요)
4. "연결이 비공개로 설정되어 있지 않습니다"가 나오면 **고급 → 계속 진행**. 내 PC에서 띄운 개발 서버라 괜찮아요.
5. 카메라 권한을 물으면 허용해요.

## 8. 막혔을 때

| 증상 | 원인과 해결 |
|---|---|
| `Port 5173 is already in use` | 다른 터미널에 `npm run dev`가 이미 켜져 있어요. 그 터미널을 쓰거나 닫고 다시 실행 |
| 화면은 뜨는데 API 요청이 실패(Network에 빨간 줄) | 백엔드가 꺼져 있어요. Docker Desktop이 켜져 있는지 보고 `npm run backend` |
| `npm run backend`가 `Cannot connect to the Docker daemon` | Docker Desktop을 실행하고 1분쯤 기다린 뒤 다시 |
| 백엔드 팀이 API를 새로 머지했는데 안 불려요 | `git -C ../docAi-be pull` → `npm run backend:restart`, 그다음 Claude에게 "○○ API 연결 확인해줘" |
| `/dev/boards`가 안 열려요 | `.env.local`이 없거나 `VITE_SHOW_BOARDS=true`가 빠졌어요. `.env.example`을 다시 복사하고 `npm run dev` 재시작 |
| `.env.local`을 고쳤는데 그대로예요 | 환경 설정은 서버가 켜질 때만 읽어요. `npm run dev`를 껐다 켜요 |
| 크롬 콘솔에 붙여 넣기가 안 돼요 | 콘솔에 `allow pasting`을 **직접 타이핑**하고 Enter |

## 9. 꼭 기억할 것

- 와이어프레임 문구는 바꾸지 않아요. 바꾸고 싶으면 먼저 물어봐요.
- 내 이슈 폴더(`src/pages/<기능>/`, `src/api/<기능>.ts`, `src/api/mocks/<기능>.ts`) 밖의 파일은 고치기 전에 물어봐요. Claude도 멈추고 물어봐요.
- 새 라이브러리는 설치하지 않아요.
- `.env.local`은 올리지 않아요(이미 막혀 있어요).
- **이슈 완료 = PR이 `dev`에 머지된 것.** 내 PC에서만 된 건 아직 완료가 아니에요.
