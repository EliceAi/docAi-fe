# 커밋

## 1. 바뀐 내용 보기
- `git status`, `git diff`, `git diff --staged`
- 지금 브랜치가 `dev`나 `main`이면 멈추고 알린다. 작업 브랜치에서만 커밋한다.

## 2. 넣으면 안 되는 것
있으면 멈추고 알린다.
- `.env.local`, `.env`(`.env.example`은 괜찮다)
- 토큰·키·비밀번호처럼 보이는 문자열
- 수정 범위 밖 파일(CLAUDE.md "수정 범위")
- `node_modules/`, `dist/`

## 3. 한 가지 일씩 묶기
- 한 커밋에는 한 가지 일만. 보드 하나, 또는 설정 하나.
- 여러 일이 섞여 있으면 나눠서 커밋하자고 제안하고, 파일별로 `git add`한다.

## 4. 메시지
```
type: 한국어 설명

(필요할 때만) 왜 바꿨는지 1~3줄
```
- type
  - `feat` 화면·기능 추가
  - `fix` 잘못 동작하던 것 고침
  - `style` CSS·모양만
  - `refactor` 동작은 같고 코드 구조만
  - `docs` 문서
  - `chore` 설정·패키지·기타
- 설명: 무엇을 했는지 한 줄, 50자 안쪽, 마침표 없음. 보드 이름과 와이어프레임 용어를 그대로 쓴다.
- 예: `feat: S15 내 계약서 목록과 빈 상태 화면 추가`, `fix: 분석 결과 조항 링크 이동 오류 수정`
- 마지막 줄에 `Co-Authored-By: Claude <noreply@anthropic.com>`

## 5. 승인 후 커밋
- 메시지와 넣을 파일 목록을 보여 주고 `이대로 커밋할까요?`
- 승인하면 커밋하고 `git log --oneline -1`을 보여 준다.
- 마지막 줄: `다음은 "PR 올려줘"라고 말해 주세요.` (아직 남은 보드가 있으면 `다음 보드 할까요?`)
