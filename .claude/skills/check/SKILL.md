# 확인

순서대로 검사하고, 마지막에 표 하나로 결과를 보여 준다. 검사만 하고 고치지 않는다. 고칠지 묻는다.

## 1. 빌드
- `npm run build`. 실패하면 오류 원인을 한두 줄로 설명하고 여기서 멈춘다.

## 2. 이슈 체크리스트
- 브랜치 이름의 번호로 `gh issue view N`을 읽고, 체크 안 된 보드가 있으면 목록으로 보여 준다.

## 3. 와이어프레임과 비교 (보드마다)
- `docs/wireframe.html`의 그 보드 HTML에 있는 문구가 화면 코드에 모두 있는지 본다. 빠지거나 바뀐 문구를 보여 준다.
- 보드 메모 `btn`의 이동이 모두 연결됐는지 본다.
- `boards.tsx`에 `render`가 연결됐는지 본다.

## 4. 규칙 위반
`git diff dev...HEAD`에서 찾는다.
- `src/pages/`에서 `fetch(` 사용
- 색을 직접 쓴 `#` 값 중 `tokens.css`·`base.css`·와이어프레임에 없는 것
- `package.json`의 의존성 추가
- 화면 주소나 로그에 이름·전화번호·주소 같은 개인정보
- `.env.local`, 토큰·키처럼 보이는 문자열

## 5. 수정 범위
- `git diff --name-only dev...HEAD`
- 이번 기능의 `src/pages/<기능>/`, `src/api/<기능>.ts`, `src/api/mocks/<기능>.ts` 밖의 파일이 있으면 "범위 밖"으로 표시한다.

## 6. 사람이 볼 것
- 확인 주소를 보드마다 준다: `http://localhost:5173/dev/boards#<보드 이름>`
- `휴대폰 크기(390px)와 PC 틀에서 직접 보셨나요?`라고 묻는다. 사람이 "봤어요"라고 해야 통과다.

## 결과
| 항목 | 결과 |
|---|---|
| 빌드 | 통과 / 실패 |
| 보드 체크 | 3/3 |
| 와이어프레임 차이 | 없음 / 목록 |
| 규칙 위반 | 없음 / 목록 |
| 범위 밖 파일 | 없음 / 목록 |
| 눈으로 확인 | 확인함 / 아직 |
