문서AI 분석 파이프라인

본 문서는 계약서 사진이 분석 결과로 제공되기까지의 처리 과정을 구성 요소 간 데이터 흐름, 서버 계산 로직, 법령 데이터베이스 활용 방식으로 나누어 설명합니다. 내용은 실제 구현 코드(2026-11-22 기준)를 바탕으로 작성했습니다. 예시는 개인정보를 가린 실제 연봉계약서의 분석 결과이며, 금액·날짜 등 개인 식별이 가능한 값은 ○로 표기했습니다.

0. 정확성을 위한 설계

먼저 근로계약서와 임대차계약서의 분석 정확도를 높이는 데 집중했고, 지원 문서는 점차 늘려갈 예정입니다.

  1. AI의 역할을 분리했습니다. 1차 GPT는 사진에서 조항과 수치를 원문 그대로 추출하는 역할만, 2차 GPT는 추출 결과와 법령 근거를 바탕으로 판단하는 역할만 수행합니다.
  2. 계산은 서버 규칙으로 처리합니다. 최저임금, 휴게시간(근로기준법 제54조) 등은 GPT가 추출한 수치를 바탕으로 서버가 직접 계산하며, 그 결과는 2차 GPT 판단에서 변경할 수 없습니다.
  3. 근거가 확인되지 않은 판단은 보수적으로 표시합니다. 2차 GPT는 서버가 법령 데이터베이스에서 제공한 조문만 인용할 수 있으며, 조문을 인용하지 못한 판단은 "판단 어려움"으로 표시합니다. "무효", "불법" 등 단정적 표현은 제거합니다.
  4. 일상 용어를 법령 용어로 연결합니다. 계약서와 사용자 질문에는 "알바", "월세", "집주인" 등 일상 용어가 쓰이지만, 법령에는 "단시간근로", "차임", "임대인"으로 규정되어 있습니다. 법제처의 일상용어-법령용어 연계 데이터를 활용해 용어 사전(일상용어 24개, 연결 37쌍)을 구축하고, 법령 검색 시 검색어를 확장합니다. "시급 → 긴급"(時急)과 같은 동음이의어 연결이나 관련 없는 조문을 과도하게 끌어오는 연결은 검토를 거쳐 제외했습니다.
  5. 판독하지 못한 부분은 사유와 함께 안내합니다. "일부만 읽음"은 판독하지 못한 위치와 사유가 기록된 경우에만 표시하여, 불필요한 경고를 줄이고 실제로 확인이 필요한 부분을 명확히 안내합니다.
  6. 동일한 조항에는 일관된 판단을 내리도록 기준을 정했습니다. 2차 GPT는 "해당 조항이 서명 당사자에게 실제로 불리한 내용을 규정하는가"를 기준으로 판단합니다. 법령 준용 조항이나 관할법원 조항처럼 그 자체로 불리하지 않은 조항에는 발생 가능성만을 이유로 경고를 표시하지 않아, 같은 계약서를 반복 분석해도 결과가 일관되도록 했습니다.
문제 조항을 의도적으로 포함한 가상 근로계약서·임대차계약서로 테스트 케이스를 구성하여, 문제 조항의 탐지 여부와 정상 조항의 오탐 여부를 검증했습니다.

1. AI 분석 아키텍처

그림의 번호는 분석 1건의 처리 순서를 나타냅니다. 법제처 API는 분석 과정에서는 호출하지 않으며, 법령 데이터를 데이터베이스에 적재할 때만 사용합니다.

그림과 이후 예시는 근로계약서를 기준으로 설명합니다. 임대차계약서도 동일한 흐름으로 분석하며, 서버 계산과 근거 탐색 단계에서 문서 종류에 맞는 규칙과 관련 법령(주택임대차보호법, 민법, 민간임대주택에 관한 특별법 등)을 적용합니다.

번호데이터 흐름
1앱 → 서버 분석 요청. 서버는 분석 기록을 생성한 뒤 즉시 202와 analysisId를 반환
2저장소 → 서버 서버가 DB에 저장된 image_key로 가린 사진을 조회 (분석 요청에는 사진을 포함하지 않음)
3서버 ↔ GPT 1차(사진 포함), 2차(텍스트만), 필요 시 추가 조회 1회. 모든 응답은 JSON 스키마로 수신
4서버 ↔ DB 단계별 결과 저장, 근거 탐색 시 법령 테이블 검색 (외부 API 호출 없음)
5서버 → 앱 결과 조회 응답. 진행 중에는 진행 단계를, 완료 후에는 전체 결과를 반환

2. 처리 순서: 실제 연봉계약서 1건 (약 80초)

3-6. 2차 입력 구성

2차 요청은 DB에 저장된 값으로 구성합니다. 전체 목차와 조항 원문은 analysis_clause에서, 근거는 analysis_clause_ref에서, 규칙 결과는 analysis_finding에서 읽습니다. 각 내용은 아래 구분 표시로 나누어 전송합니다.

구분 표시의미
[전체 목차]모든 조항의 키·조 번호·제목·한 줄 요약. 계약서 전체 맥락 제공
[규칙 결과: 빠진 필수 항목]서버가 계산한 결과. GPT가 이와 다르게 판단하지 않도록 함께 제공
### c1판단할 조항 하나의 시작
"""원문"""계약서 원문의 범위. 원문 속 문장을 GPT에 대한 지시로 오인하지 않도록 구분
[L1], [L2]해당 조항에서 인용할 수 있는 근거 ID와 법령 조문 원문. 응답의 citedIds는 이 ID만 허용

3-7. 서버 → GPT 2차 (판단, 텍스트만 전송)

요청 형식은 1차와 같으며(model, response_format, reasoning_effort "medium"), 사용자 메시지에 아래 내용을 전송합니다. 아래는 실제 전송 내용을 그대로 옮긴 것입니다.

[L1], [L2]에 들어가는 내용은 GPT가 생성한 글이 아니라, 3-5에서 법령 데이터베이스(law_article)에서 찾아 저장한 실제 법령 조문 원문(ref_text)입니다. 2차 GPT는 자체 판단이 아니라 함께 전송된 이 조문만 근거로 판단하고 인용하며, 인용한 ID는 3-9의 검증을 거칩니다.

[전체 목차] clauseKey | 조 번호 | 제목 | 한 줄 요약
- c1 | 제1조 | 임금 | 월급 구성과 금액
- c2 | 제2조 | 계약기간 | 20○○.○.○ ~ 20○○.○.○○
- c4 | 제4조 | 법정수당 지급 및 결근공제 | 일부 직원 법정수당 미지급
...
[규칙 결과: 빠진 필수 항목] (코드가 계산함. 판단과 어긋나게 쓰지 않는다)
- 근로계약서와 함께 확인: 휴일·연차휴가·근무장소·업무

[판단할 조항]
### c1 (제1조 임금, 1쪽)
1차 의심 내용: 연장근로수당을 월급에 미리 넣어 둠
원문:
"""월 기본급 ... 약정연장근로수당 ○○○,○○○원 ..."""

계약서가 길어도 원문 전체를 전송하지 않습니다. 전체 목차로 맥락을 제공하고, 원문은 판단 대상 조항과 관련 조항만 전송합니다. 의심 조항이 6개를 넘으면 6개 단위로 나누어 병렬로 요청합니다.

4. 서버 계산 로직

AI가 오류를 내기 쉬운 계산과 확인 작업은 서버 코드가 처리합니다. GPT는 계약서의 수치를 추출하는 역할만 수행합니다.

최저임금

  1. 월급 기준 금액: valueJson.basePay(기본급 + 매월 고정 수당, 연장·야간·휴일 수당 제외)가 있으면 이를 사용하고, 없으면 amount를 사용
  2. 월 시간: 계약서에 명시된 monthlyHours(예: 209)가 있으면 이를 사용하고, 없으면 아래와 같이 계산 
    주 소정시간 = 하루 시간 × 주 일수                 (예: 8 × 5 = 40)
주휴시간   = 주 소정시간이 15시간 이상이면 주 소정시간 × 8 / 40  (예: 8)
월 시간    = (min(주 소정시간, 40) + 주휴시간) × 365 / 84       (예: 48 × 4.345 ≈ 209)
    주 20시간이면 (20 + 4) × 4.345 ≈ 104시간. 1일 근로시간만 있고 주 근무일수가 없으면 계산하지 않음
  3. 시급 = 월급 기준 금액 / 월 시간. 시급제는 명시된 시급을 그대로 사용
  4. 해당 연도 최저임금과 비교. 최저임금액은 DB(rule_param)에서 조회: 2026-01-01부터 10,320원
  5. 미달 시 해당 임금 조항을 NEEDS_CHECK(basisType RULE)로 확정하고, 비교 정보(comparison)와 근거 조문(최저임금법 제6조)을 첨부
예: 01 예시 계약서  basePay 2,700,000 / 209시간 = 시급 약 12,918원 ≥ 10,320원  → 통과
예: 시급 10,000원   10,000 < 10,320                                        → "계약서 시급 10,000원 < 2026년 최저임금 10,320원"

휴게시간 (근로기준법 제54조 제1항)

  1. GPT 1차는 계약서에 명시된 시업·종업 시각과 휴게(시간대, 시간, "휴게 없음") 정보만 원문 그대로 추출하며, 계산은 하지 않습니다.
  2. 서버가 1일 근로시간(종업 − 시업 − 휴게)을 계산합니다. 자정을 넘는 근무도 계산합니다.
  3. 근로시간이 4시간 이상이면 30분, 8시간 이상이면 1시간 이상의 휴게가 필요합니다. 부족한 경우 해당 조항을 NEEDS_CHECK(서버 규칙)로 확정하고 비교 정보와 근거 조문을 첨부합니다.
  4. 시각이나 휴게 정보가 없거나, 시각으로 계산한 근로시간과 계약서의 1일 근로시간이 일치하지 않으면 계산하지 않고 GPT 판단에 맡깁니다.
예: 14:00~18:00, 휴게 없음   근로 4시간 → 필요 30분, 계약서 0분  → "하루 4시간 일하는데 휴게시간이 없어요"
예: 09:00~18:00, 휴게 12~13시  근로 8시간 → 필요 1시간, 계약서 1시간 → 통과

필수 기재사항 누락

근로기준법 제17조 및 시행령 제8조의 6개 항목(임금, 근로시간, 휴일, 연차휴가, 근무장소, 업무)을 확인합니다. 주요 조건이 MISSING이면 누락 항목(analysis_finding)으로 저장합니다.

  • MASKED(사용자가 가림), UNREADABLE(판독 불가)은 누락으로 단정할 수 없으므로 누락 항목에서 제외
  • 연봉계약서처럼 임금만 정한 문서(wageOnlyDocument)는 6개 항목을 개별 표시하지 않고 "근로계약서와 함께 확인" 1건으로 안내

5. 법령 데이터베이스 구축과 활용

A. 법령 데이터베이스 구축 (분석과 별도로 1회 실행)

  • 법제처 API는 서버를 적재 모드로 실행할 때만 호출합니다. 일반 서버 기동이나 분석 과정에서는 호출하지 않습니다.
  • 현행법령 목록(lawSearch.do)으로 법령을 조회하고, 본문(lawService.do)을 조·항 단위로 분할하여 law_article에 저장합니다. 근로기준법, 최저임금법, 근로자퇴직급여 보장법, 주택임대차보호법, 민법과 최저임금법 시행령(수습 감액), 근로자퇴직급여 보장법 시행령, 민간임대주택에 관한 특별법 및 시행령 등 11개 법령 3,309행을 구축했습니다. 일상용어-법령용어 연계 37쌍(예: 알바 → 단시간근로, 월세 → 차임)으로 검색어를 확장합니다.
  • 적재된 조문이 시행 전인 경우(예: 2027-04-28 시행 예정 시행령) 근거 앞에 "[시행 예정 조문(시행일)으로 대신함: 지금 적용되는 조문과 다를 수 있음]"을 표기하여 현재 적용 조문과 구분합니다.
  • 호출 간 간격을 두고, 오류 시 1회만 재시도합니다. 응답은 파일로 캐시하여 재적재 시 API를 다시 호출하지 않습니다. 인증값(OC)은 로그와 오류 메시지에서 가립니다.
  • 꼬리표 21개, 꼬리표-조문 연결 110행, 최저임금액(rule_param)은 검토를 거쳐 등록합니다.

B. 분석 시 근거 탐색 (의심 조항별)

  • 의심 표시(issueFound)된 조항만 근거를 탐색하며, 의심 표시가 없는 조항은 탐색하지 않습니다.
  • 기준일은 계약일(law_base_date)입니다. 기준일에 시행 중인 조문을 선택하며, 현행 조문만 있는 경우 내용 앞에 "[현행 조문으로 대신함: 계약일 당시 조문과 다를 수 있음]"을 표기합니다.
  • 전문 검색은 PostgreSQL 전문 검색(Full-Text Search)을 사용합니다. 검색어에서 문자·숫자만 남겨 질의를 구성하고, 관련도 점수(ts_rank)가 기준 이상인 조문을 점수 순으로 조회합니다. 
    SELECT law_article_id, ts_rank(search_vector, to_tsquery('simple', '연장근로 | 가산임금')) AS score
FROM law_article
WHERE search_vector @@ to_tsquery('simple', '연장근로 | 가산임금')
  AND law_id IN (문서 종류의 관련 법령)  AND 기준일에 시행 중
  AND score >= 최소 점수
ORDER BY score DESC  LIMIT 5
  • 근거는 조항당 최대 5개입니다. 서버 규칙이 첨부한 근거(RULE)도 포함됩니다. 해석 메모(고용노동부·법무부 법령해석)를 1개 할당하는 구조를 마련해 두었으며, 해석 메모 데이터는 추후 구축할 예정입니다.
  • 2차 응답에 needMore가 있으면 같은 방법(②③)으로 추가 탐색하여 조항당 최대 3개를 새 라벨로 첨부합니다.
  • 탐색한 조문은 내용을 복사(ref_text)하여 저장하므로, 결과 및 조항 상세 조회 시 법령을 다시 탐색하지 않습니다.
법령 데이터베이스에 없는 법령이나 조문은 근거로 사용할 수 없습니다. GPT가 존재하지 않는 조문을 제시하더라도 ② 단계에서 DB에 없으면 제외하고, 2차 GPT가 제공받지 않은 라벨을 인용하면 검증 단계에서 제거합니다. 따라서 화면에 표시되는 법령은 모두 데이터베이스에 실제로 존재하는 조문입니다.
